# SKE-02 Gateway (esp8266_gateway_fork)

ESP8266_RTOS_SDK v3.4 (freedib-форк, порт IDF-v3!), чистый C + SPA.
Подключённый прибор — расходомер SKE-02 по UART0 (текстовая консоль),
шлюз поднимает веб-интерфейс (SPA ~15 КБ gzip) и modbus tcp/502.

## Сборка и запуск

- **PlatformIO для RTOS-SDK НЕ прошивает таблицу разделов** — `tools/flash_parts.py` шьёт автоматически после upload. Смена partitions.csv требует ручной прошивки 0x8000.

```
pio run                                # сборка (src/pages.h пересобирается сам pre-скриптом)
pio run -t upload                      # прошить
pio run -t ota                         # OTA-образ -> gw_update.bin
python tools/pages.py build            # вручную: www/* -> src/pages.h + www/app.html
python tools/mock_server.py            # мок на :8099 (8099 занят — убить процесс на порту)
MOCK_AP=1 python tools/mock_server.py  # мок в режиме точки доступа
python tools/ram_report.py             # сводка статики/кучи по .map (после pio run)
```

- pio: `~/.platformio/penv/Scripts/pio`. SDK: `~/.platformio/packages/framework-esp8266-rtos-sdk`.
- Страница — ЕДИНЫЙ инлайненный бандл `app.html`. Мок инъектирует версионирование и `window.__errs`.
- **`app.html` и `src/pages.h` — ГЕНЕРИРУЕМЫЕ, НЕ править** (tools/pages.py из www/*). Править только www/*.html и www/*.js.

## Протокол консоли прибора — СЛОВА

ECHO, INFO, DATA, HELP, GET id, SET id val, RUN id, PASS [pw], WHERE id, LOCK, REBOOT, RTC, EEPROM, DUMP, LIST s [m [n]], MB <hex>. Регистронезависимо.

## Конвейер данных

1. **Задача meter** (`ske02.c`, стек 3584) опрашивает `DATA` каждые 200 мс (5 Гц). Кадр — 2 строки, ЦЕЛОЧИСЛЕННЫЙ формат (x1000/x10000, экономия стека Btn на приборе; %f у прибора снят).
2. Поля кадра строки 2 (7-8) = **МАРКЕР ПРАВКИ** (edit_id, edit_cnt): прибор пишет в storePropertyValue при каждой записи параметра. Шлюз по маркеру синхронизирует ОДИН пункт (`GET <id>`) или делает обход значений (delta>1). **cfg_rev УДАЛЁН** — заменён маркером. Уход cnt назад = ребут прибора → полный relist.
3. **Свои SET** (из /api/set): OK-строка уже обновила NVS точечно (tree_set_value), GET не нужен. Счётчик sLocalSets.
4. Производные (rate/total/gtotal) — `vals_derive()` ske02.c, единицы из enum-параметров дерева.
5. **`GET /api/values?since=N`** — единственный периодический запрос (1 Гц). Ответ ЧАНКАМИ. График — тем же ответом: `&s0=src&c0=cursor[&l0=lo&h0=hi]` → `"chart":[{i,n,f,total,t0,dt,lo,hi,b64}]`.
6. Страница (index.js pollLoop): таймаут 5с, интервал ≥max(1с, 3×RTT), при ошибках откат ×2 до 10с. Пачка replaySeq по 200мс.
7. **График**: ОДИН виджет максимум, кольцо int8[1024] в куче (malloc при первом появлении графика на панели, `s0` в запросе). Шкала: авто-прогрев по первым 5 значениям ИЛИ фиксированная уставками (при auto=false, `&l0=&h0=`). Смена шкалы = перемасштабирование кольца (не сброс). Курсор `c0` — последовательное вычитывание от индекса.

## Дерево параметров — в NVS, не в ОЗУ

- Парсер листинга потоковый: `proto_parse_line` → `on_param` → `tree_write` → NVS "p<id>". Значения вне листинга → `on_value` → `tree_set_value` (пишет ТОЛЬКО если изменилось — flash не трогается при совпадении).
- **tree_commit: count = maxId+1, НЕ liveCount** — страница итерирует id=0..count-1; при liveCount < maxId+1 (дыры в нумерации) хвост записей лежал в NVS, но не отдавался.
- **SKE_MAX_PARAMS = 224** (был 192; seenMap выходил за границу). Guard `id < SKE_MAX_PARAMS` в парсере.
- **ТИПЫ: H32, H8, H16, MAC, IP добавлены** в type_by_token (были пропущены — 5 типов параметров молча выбрасывались). SKT_H32=15, SKT_MAC=16, SKT_IP=17 (в конце enum, чтобы не сдвинуть существующие).
- Чтение: `tree_get(id, TreeRec*)`. TreeRec ~755Б — на стеке meter рвал канарейку, теперь static в вызывающих.
- ЛИСТИНГ ПОУРОВНЕВЫЙ: `LIST s` (0=Измеритель, 1=Основные, 2=Система); `LIST s m` — от m-го подменю. DFS-очередь: **3 Б/слот** [секция,подменю,подподменю] × 96 (была 40×14 строк). Буфер 2300Б один раз.
- tree_commit стирает записи не встретившиеся в проходе (seenMap) — дублеи от сдвига id не копятся.
- Прибор первым: листинг ДО WiFi (девственная куча, 2300Б malloc гарантирован).

## Фичи шлюза из дерева прибора

Подменю «Wi-Fi gateway» (Система): WEB panel / Modbus TCP/IP / OTA update (bool). Шлюз ищет по латинским токенам (WEB/Modbus/OTA) и применяет:
- WEB off → httpd_stop (все соединения рвутся); on → web_start
- Modbus off → mb_pass_enable(false): новым отказ, живущие рвутся на следующей транзакции
- OTA off → /api/ota/* отвечают 403
Параметров нет (старый прибор) → всё включено. Recovery: выключил «Веб» → вернул с клавиатуры или через modbus.

## Синхронизация правок (маркер edit_cnt/edit_id)

| Сценарий | Действие шлюза |
|---|---|
| Наш SET (веб) | Молча (NVS уже обновлён OK-строкой), `own set, no resync` |
| Клавиатура, одна правка (delta=1) | `one_param_sync(id)`: одна команда GET, ~30мс |
| Клавиатура, несколько (delta>1) | `sweep_values()`: GET по всем, NVS только изменившиеся |
| Ребут прибора (cnt назад) | Полный relist (структура могла смениться) |
| Первый кадр после листинга | Принять cnt; если ≠0 → sweep (правки за время листинга) |

## ESP8266-специфика

- **httpd однопоточный, 7 сокетов.** Стек 8192. Всё чанками.
- **`%f` ТОЛЬКО в httpd** — per-task reent сломан; в meter — fmt_float/целые.
- Логи DBG — UART1/GPIO2. UART0 — консоль прибора.
- **ets_putc (сильный символ)** — глушит wifi-блоб в UART0 (SDK пишет прямо в FIFO).
- Куча ~20-28К. TCP_SND_BUF=1440.
- AP-портал: 192.168.4.1 (дефолты адаптера).
- **НЕ подключаться к живому шлюзу (192.168.0.41) без явной просьбы** — 3 httpd-слота + lru-purge.
- **Heredoc калечит `\n`** — строки C/JS править инструментом Edit.
- В JS if/else ОБЯЗАТЕЛЬНО фигурные скобки.

## Диагностика

- `curl /api/info` — heap/rssi/uptime
- `curl "/api/values?since=0&s0=rate&c0=0"` — график напрямую
- `curl -X POST -d 'id=94&v=...' /api/set` — ввод без браузера
- `python tools/ram_report.py` — статика/куча по .map
- addr2line: `~/.platformio/packages/toolchain-xtensa/bin/xtensa-lx106-elf-addr2line.exe -f -e .pio/build/esp8266_modern_rtos/firmware.elf 0xADDR`
- OTA: `-H "Expect:"` обязателен на больших POST

## OTA шлюза

Два слота: ota_0@0x20000, ota_1@0x120000 (разница ровно 1М — окно кэша). otadata@0x1A000. esp_ota_begin ТОЛЬКО с точным content_len.

## Грабли (оплачено)

- **TreeRec на стеке meter** — двойной (~1.5К) в one_param_sync рвал канарейку. Все TreeRec в static.
- **line_to_parser русифицирует С РАСШИРЕНИЕМ** — всегда разбирать КОПИЮ в lbuf[512]/sParseBuf[512], не value_line[128].
- **Отрицательный float → (unsigned long) на AVR = wrap к 2^32** — кламп X1000()/X10000() перед кастом в DATA-кадре прибора.
- **queue[40][14] строк** — DFS молча ронял подменю при полном стеке. Теперь 3-байтовые слоты ×96.
- **type_by_token пропускал H8/H16/H32/MAC/IP** — 5 типов параметров выбрасывались молча (return 0xFF).
- **liveCount вместо maxId+1 в tree_commit** — хвост id (179-180) не отдавался страницей при дырах в нумерации.
- **chart_cfg memset затирал buf-указатель** — слот навсегда замолкал (сохранять указатель при сбросе).
- **Смена шкалы графика = сброс кольца** потеря истории при загрузке страницы (уставки приходят через 3с). Теперь: перемасштабирование int8 на месте.
- **Курсор графика впереди рестартнувшего кольца** — n=0 навсегда. Сброс если total ≤ курсора.
- **cfg_rev больше НЕТ** — прибор его не шлёт. Триггер = edit_cnt (маркер).
