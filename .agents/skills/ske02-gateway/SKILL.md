# SKE-02 Gateway (esp8266_gateway_fork)

ESP8266_RTOS_SDK v3.4 (freedib-форк, порт IDF-v3!), чистый C + SPA.
Подключённый прибор — расходомер SKE-02 по UART0 (текстовая консоль),
шлюз поднимает веб-интерфейс (SPA ~15 КБ gzip) и modbus tcp/502.

## Сборка и запуск

```
pio run                                # прошивка (src/pages.h пересобирается сам pre-скриптом)
pio run -t upload                      # прошить
python tools/pages.py build            # вручную: www/* -> src/pages.h + www/app.html
python tools/mock_server.py            # мок на :8099 (8099 занят — убить процесс на порту)
MOCK_AP=1 python tools/mock_server.py  # мок в режиме точки доступа
```

- pio: `~/.platformio/penv/Scripts/pio`. SDK: `~/.platformio/packages/framework-esp8266-rtos-sdk` (это тот самый форк, им же и собирается).
- Страница — ЕДИНЫЙ инлайненный бандл `app.html` (браузер не скачивает отдельные js-файлы — всё внутри). Мок инъектирует в него версионирование и `window.__errs` (JS-ошибки страницы — проверять после КАЖДОЙ правки клиента).
- Тестовый webview агента кэширует инлайненные страницы вопреки no-store — если поведение странное, сначала проверь, что отдаёт `curl -s http://127.0.0.1:8099/ | grep <новая-строка>`.

## Конвейер данных (главное)

1. **Таск прибора** (`ske02.c`) опрашивает `'m'` каждые 200 мс (5 Гц), независимо от браузера. Новый кадр — 2 строки: `m,frequency,rateMLPM,totalml_plus,totalml_minus,gtotalml` + `kf_value,pulses,batch,status,setpoint,isr` (hex-флаги).
2. Производные (rate/total/gtotal в единицах прибора) считает шлюз — `vals_derive()` в ske02.c: единицы берёт из enum-параметров дерева («Расход/Период/Объём/Общий»).
3. Каждый снимок → кольцо `ske02_valring` (8 шт, ~700 Б) + общий кэш под мьютексом `sLock` (httpd берёт лок на 50 мс, иначе кэш — НИКОГДА не ждать прибор в обработчике).
4. **`GET /api/values?since=N`** — единственный периодический запрос (1 Гц, адаптивно): конверт (link/ready/now/ap/ip/ssid) + `seq` пачка снимков новее N; при since=0 — один свежий. Ответ — ЧАНКАМИ по снимку (никаких malloc/больших буферов на запрос — куча мала).
5. Страница (`index.js` pollLoop): таймаут 5 с (AbortController), интервал >= max(1с, 3×RTT), при ошибках откат ×2 до 10 с. Пачку `replaySeq(seq, off)` проигрывает по 200 мс: цифры виджетов обновляются 5 Гц при 1 запросе/с. `off = Date.now() - d.now` — смещение серверных часов, обязательно передавать в replaySeq.
6. График (`shared.js`, CHARTS_ON): питается из тех же проигрываемых снимков (chartAppend с серверским ts) — 0 запросов и 0 байт на ESP. Рисование: медиана-3 → мин/макс-конверт по колонкам → автоскейл «красивая сетка»+гистерезис → разрывы на дырах >3 с. Окно сдвинуто назад на CHART_EDGE_MS (точки рождаются за правым краем).

## ESP8266-специфика (выучено кровью)

- **httpd однопоточный, 7 сокетов.** Один медленный клиент = стоит весь сервер. Всё тяжёлое — чанками, никаких больших ответов одним куском.
- **Стек httpd = 8192, не меньше**: h_scan держал ~2.7 КБ локальных буферов — на 6144 стек переполнялся и молча калечил кучу.
- Таймауты сокета — поля `cfg.recv_wait_timeout`/`send_wait_timeout` (В СЕКУНДАХ; `..._ms` из IDF-v4 здесь НЕТ — сборка падает). Стоят 2/4 с.
- **`esp_log_level_set` — no-op**: в этом SDK работает только при CONFIG_LOG_SET_LEVEL (выключен). Логи SDK глушатся компиляционно: `CONFIG_LOG_DEFAULT_LEVEL_NONE` в sdkconfig(.defaults).
- Логи прошивки (DBG) — **UART1/GPIO2, 115200**. UART0 — консоль прибора, всегда чистая. Раз в 30 с — сводка `gw: sta <ip> rssi <n> heap <h> min <m>`; провалы кучи — `gw: heap dip <n> at <s>`.
- Куча в покое ~20-28 КБ. Убраны: chartbuf истории (4 КБ), статические буферы скана (в кучу на время), valring урезан. TCP_SND_BUF=1440 (1 сегмент) — пиковые pbuf'ы вдвое меньше.
- **AP-режим (портал)**: открытая сеть `SKE02-GW-XXXX`, адрес **192.168.4.1** (дефолты адаптера! свою подсеть не назначать — AP-start событие асинхронно перетирает), B+G (`esp_wifi_set_protocol` до старта), PS_NONE. Captive-DNS на udp/53 в STA-режиме самоудаляется через 120 с.
- **Compat-слой событий постит `IP_EVENT_AP_STAIPASSIGNED` с data=NULL** — разыменование data роняло таск событий в немой wdt-reset (rst cause:4). Любой обработчик события проверяй на NULL.
- Классика багов этого порта: mutex в `ske_query_values` отдавался только при ok (битый ответ прибора вешал сервер навсегда) — всегда `xSemaphoreGive` по всем путям.

## Среда разработки

- **Heredoc в этой среде калечит `\\n`** — строки C/JS с бэкслешами править инструментом Edit, не bash-скриптами с heredoc.
- В JS-правках с if/else ОБЯЗАТЕЛЬНО фигурные скобки — один пропущенный return без скобок ломал все виджеты (TypeError CHSRC undefined).
- Мок — полная модель: фоновые сэмплеры 5 Гц (значения в кольцо) и 1 Гц, те же форматы ответов. После правок формата правь и мок.
- Диагностика прямо в UI: график в фазе накопления показывает `(точек N, вызовов M, причина, src→поле | ok:1 seq:N rate:X)` — читай её первой при проблемах графиков.
