# SKE-02 ESP8266 Gateway

Шлюз на ESP8266 для расходомера SKE-02 (прошивка Totalizer_FreeRTOS).
Подключается к сервисной консоли прибора (USART0), показывает все его
параметры в веб-интерфейсе и отдаёт их SCADA по Modbus TCP.

Возможности:

- **Веб-сервер со страницей авторизации Wi-Fi.** Без сохранённых кредов
  (или если сеть недоступна) шлюз поднимает точку доступа `SKE02-GW-XXXXXX`
  (пароль `ske02setup`) с captive-порталом: любая страница открывает форму
  ввода SSID/пароля, список найденных сетей прилагается. Креды хранятся
  в EEPROM (флеш-сектор), меняются и через `/wifi` в рабочем режиме.
- **Приём данных по UART.** Текстовый протокол сервисной консоли
  ([include/console.h](../Totalizer_FreeRTOS/include/console.h); бинарный
  протокол из прошивки удалён): каждая транзакция завершается приглашением
  `SKE02> `. Обнаружение: `e` (эхо выкл) → `i` (версия, количество
  параметров) → **один** полный листинг `l` — из него берутся сразу имена,
  структура меню, типы, read-only, диапазоны/списки значений и сами
  значения. Фонового опроса **нет вообще** — это параметры настроек, они
  редко меняются: полный листинг `l` выполняется только по кнопке
  «Обновить» (POST `/api/refresh`, ~1.5 с), при обнаружении,
  «Пересканировать» и после потери связи. Запись —
  `s <id> <значение>` (ответ `OK` + строка с фактическим
  проклампленным значением; TIME/DATE передаются сырыми секундами —
  консоль принимает только числа). Команды меню — `x <id>`, разблокировка
  доступа — `p <пароль>` (`access:…`; `ERR access`/`ERR wait` = неверный
  пароль / блокировка 30…240 с). Перезагрузка прибора — `r`.
  Русские имена/значения конвертируются из смешанного
  латинско-кириллического набора консоли в чистую кириллицу.
- **Мониторинговое окно (главная страница).** Живые измерения — структура
  `MeterData_t` (`flowmeter1`) прибора: шлюз раз в секунду опрашивает
  консольную команду `m` (три CSV-строки в порядке членов структуры) и
  отдаёт JSON `/api/values`. Значения выводятся карточками по типам
  (float/u32), названия — как у членов структуры (frequency, rate,
  total, gtotal, pulses…); побитовые члены setpoint/status/isr —
  наборами чипов с именами флагов FSETPOINT_/FSTATUS_/FISR_
  (RATEQMAX…PREEMPTION, ACCESERROR…LOGFULL, DOUT0…PHASE), зажжённый
  чип = установленный бит. Настройки прибор при этом не тревожатся —
  `m`-кадр занимает ~170 байт.
- **Веб-интерфейс параметров.** Всё дерево параметров прибора спрятано за
  кнопку **«⚙ Настройки»** в заголовке (тумблер, свёрнуто по умолчанию —
  основная страница остаётся чистой). Внутри — трёхуровневая навигация
  как в меню прибора: кнопки меню первого уровня (Измеритель / Основные / Система / Журнал;
  корневое меню «Настройки» без кнопки) → **табы** меню второго уровня
  (внутри секции; параметры самой секции — в табе «Общие») → **подтабы**
  третьего уровня. Таблицы линеаризации («Прямое/Реверс направление»)
  выводятся сеткой пар **F|V** (F01↔V01 … F10↔V10) вместо длинного
  списка. Изменения накапливаются (строка подсвечивается) и
  отправляются кнопкой **«Применить»**; **«Обновить»** перечитывает
  значения (автообновления нет — значения не меняются под руками). Для
  каждой секции первого уровня — своё поле **пароля меню**: при применении
  шлюз сначала разблокирует доступ командой `p <пароль>`, затем пишет
  `s`/`x`; неверный пароль и блокировка (эскалация 30…240 с на приборе)
  показываются сообщением. Параметры-пароли (U32 menu_pass[]) рисуются
  полем типа password и всегда маскируются `******`. Пункты-команды меню
  (тип CMD) — кнопкой **«Выполнить»** с подтверждением (`x <id>`).
  Редактор по типу:
  - bool/enum — комбобокс со списком значений прибора (значение показывается
    текстом опции, как на LCD прибора);
  - float — текстовое поле чисел без спиннера, диапазон — подсказкой;
  - U32 — поле на 6 цифр;
  - U8/I8/U16 (и H8/H16/I16) — спинбокс с min/max;
  - TIME — ввод чч:мм, DATE — дд.мм.гг (как в меню прибора, меняется только
    редактируемая часть значения).
  Автообновление раз в 2 с, фильтр ищет по всем секциям сразу (принимает и
  русский, и оригинальную латиницу), перезагрузка прибора, настройка
  периода опроса. Адрес: IP шлюза или `http://ske02-gw.local/`.
- **Руссификация текста прибора.** Консоль прибора выдаёт кириллицу с
  совпадающими по начертанию латинскими глифами HD44780 (А→A, В→B, Е→E,
  К→K, М→M, Н→H, О→O, Р→P, С→C, Т→T, Х→X, Ь→b, а→a, е→e, о→o, р→p,
  с→c, у→y, х→x — таблица RussianROMLetters прошивки). Шлюз конвертирует
  их обратно в кириллицу **пословно**: буква заменяется только в словах,
  уже содержащих настоящую кириллицу, поэтому настоящая латиница
  (Qmax, UTC, CRC, HW, F01, K-фактор) не трогается. Поиск теперь работает
  от чисто русского набора.
- **Modbus TCP slave** на порту 502 (FC 03/04/06/10), см. карту ниже.

## Сборка и прошивка

Две конфигурации (`default_envs` в `platformio.ini`):

- **`nodemcuv2_usbdbg`** (по умолчанию, для отладки на столе): весь лог —
  на UART0, то есть в USB-порт платы (COM11); линия прибора отключена.
  Первые ~200 мс мусора в мониторе — это загрузчик ROM на 74880, дальше
  пойдут строки `[gw] ...`. Нормально.
- **`nodemcuv2`** (рабочая): UART0 занят прибором, лог — на UART1 (GPIO2).
  В мониторе USB при этом видны только бинарные PING-кадры `0xAA` и шум
  загрузчика — это не ошибка.

```bash
pio run                                   # сборка текущей default_env
pio run -t upload                         # прошивка текущей default_env
pio run -e nodemcuv2 -t upload            # рабочая прошивка
pio device monitor                        # лог (115200)
```

Команды выполняются из каталога проекта (полный путь к pio, если его нет в
PATH: `%USERPROFILE%\.platformio\penv\Scripts\pio.exe`).

ESP8266 работает только в диапазоне **2.4 ГГц** — сети 5 ГГц он не видит.
Плата по умолчанию `nodemcuv2`; для голого модуля ESP-12E/F замените
`board = esp12e` в `platformio.ini`.

## Подключение

| ESP8266 | SKE-02 (разъём сервисной консоли) |
|---|---|
| GND | GND |
| TX (GPIO1) | RXD прибора |
| RX (GPIO3) | TXD прибора **через делитель 1:2** (см. ниже) |

**Внимание, уровни.** ATmega128 @16 МГц — 5-вольтовая логика, ESP8266 —
3.3 В и **не толерантен к 5 В**. Вывод TX прибора подключайте к RX шлюза
через резисторный делитель (например 1 кОм / 2 кОм). Обратное направление
(3.3 В → прибор) работает напрямую: VIH ATmega128 = 0.6·VCC = 3.0 В.

Скорость порта — 115200 8N1. Отладочная печать шлюза идёт через UART1
(GPIO2, только TX) на 115200 — подключайте USB-UART к GPIO2, а не к GPIO1/3
(они заняты прибором).

## Стенд пользователя (COM28, перемычка, BOOT)

USB-UART на COM28 один, и он **коммутируется перемычкой ATmega128 ↔ ESP8266**:

- перемычка в сторону ESP8266 — COM28 видит шлюз (прошивка, логи usbdbg);
- перемычка в сторону ATmega128 — COM28 видит сервисную консоль прибора
  (конфигуратор, `--selftest`-утилиты);
- для работы шлюза с прибором перемычка соединяет линии ATmega128 ↔ ESP8266.

Прошивка ESP: кнопка **BOOT** на плате — если авто-сброс в бутлоадер
срывается («Timed out waiting for packet header»), нажать и держать BOOT
в момент начала загрузки; надёжный вариант — 115200 c
`--connect-attempts 8`.

**Правило для ассистента: перед прошивкой всегда делать паузу и явно
спрашивать подтверждение у пользователя** — только он коммутирует
перемычку и держит BOOT.

## Веб-API

| Метод и путь | Назначение |
|---|---|
| `GET /` | дашборд параметров (в режиме портала — форма Wi-Fi) |
| `GET /wifi` | страница настройки Wi-Fi |
| `GET /api/info` | статус: версия прибора, связь, IP, RSSI, uptime, heap |
| `GET /api/params` | все параметры JSON: `{i,t,r,n,s,g,v,w,lo,hi,o,a}` — id, тип, сырое значение, имя, секция, подменю, значение, доступность записи, границы, список опций, возраст значения |
| `POST /api/set` | `id=<N>&v=<значение>` — запись параметра (WRITE) |
| `POST /api/rescan` | полный перескан прибора |
| `POST /api/reboot` | перезагрузка прибора (BC_REBOOT) |
| `POST /api/setpoll?poll=20` | период опроса UART, единицы 100 мс |

Идентификаторы параметров — те же, что в консоли (`l`, `g`, `s`) и
конфигураторе; нумерация меняется при изменении меню прибора, поэтому после
обновления прошивки прибора нажмите «Пересканировать».

## Modbus TCP (slave, порт 502)

Функции 03/04/06/10, unit id не проверяется. Порядок слов как в прошивке
прибора: 32-битные значения занимают два регистра, **младшее слово — по
младшему адресу**.

### Input registers (RO, FC04)

| Рег. | Тип | Смысл |
|---|---|---|
| 0 | U16 | статус: б0 — связь с прибором, б1 — таблица параметров готова, б2 — WiFi STA подключён, б3 — режим точки доступа |
| 1 | U16 | количество параметров прибора |
| 2–3 | U32 | аптайм шлюза, с |
| 4 | I16 | RSSI, dBm |
| 5 | U16 | секунд с последнего успешного обмена с прибором |
| 6 | U16 | свободная heap, КиБ |
| 7–10 | U16×4 | октеты IP-адреса шлюза |

### Holding registers (RW, FC03/06/10)

| Рег. | Тип | Смысл |
|---|---|---|
| 0 | U16 | CONTROL: 1 — перескан прибора, 2 — перезагрузка прибора, 3 — перезагрузка шлюза |
| 1 | U16 | период опроса UART, ×100 мс (1–255, по умолчанию 20) |
| 2–99 | — | зарезервировано, читается как 0 |
| 100+2·id | — | **параметр `id`**: младшее слово сырого значения |
| 101+2·id | — | старшее слово (только для u32/float) |

Формат значений параметров — сырые байты консоли, little-endian: float —
IEEE-754 в двух регистрах, u32 — целое в двух, u16/u8/bool/enum — младший
регистр (старший читается как 0). Пример: параметр 7 (float) занимает
регистры 114–115.

Запись: FC10 по обоим словам фиксируется сразу; одиночные FC06 буферизуются
по слову и фиксируются, когда записано второе слово пары. Прибор клампит
записанное значение — читайте назад фактическое. Ошибки: недоступный
параметр → ILLEGAL DATA ADDRESS, прибор не отвечает → SLAVE DEVICE FAILURE.

## Инструменты (стенд без пайки)

- `tools/uart_bridge.py COM11 COM28 [--esp-reset]` — программный мост между
  USB шлюза и USB сервисной консоли прибора: шлюз «видит» прибор через ПК.
  Порт прибора открывается с опущенными RTS/DTR (RTS заведён на RESET).
- `tools/discovery_check.py`, `tools/ske02_sim.py` — работают со СТАРЫМ
  бинарным протоколом (удалён из прошивки) и больше не применимы к прибору;
  оставлены как исторические образцы.
- `tools/test_parser.cpp` + `run_parser_test.bat` — хост-тест текстового
  парсера шлюза (зеркало parseParamLine) по снятому листингу `ske_l.txt`:
  имена, секции, опции, диапазоны, значения, read-only.
- `tools/ui_mock.py [port]` — офлайн-мок веб-интерфейса: отдаёт дашборд
  из `src/web.cpp` и фейковые `/api/*` по снятому листингу — правки UI
  можно проверять в браузере до прошивки ESP.

```
src/
  main.cpp        режимы WiFi (STA / AP-портал), DNS, mDNS, LED, цикл
  ske02.{h,cpp}   клиент консоли: кадры+CRC8, кэш параметров, опрос
  web.{h,cpp}     HTTP: портал, дашборд, JSON API

```

## Ограничения

- Id параметров привязаны к структуре меню конкретной прошивки прибора
  (это свойство протокола консоли) — после смены прошивки прибора обязателен
  перескан.
- Значения TIME/DATE показываются как сырые u32 (секунды/дата в формате
  прибора); enum/bool — числом.
- В момент записи параметра (веб или Modbus) цикл блокируется на время
  UART-транзакции (до ~1 c при отсутствии ответа).
