# ESP8266 Gateway for the SKE-02 flow meter — ESP8266_RTOS_SDK port

Форк проекта [esp8266_gateway](../esp8266_gateway), переписанный с Arduino (C++)
на **ESP8266_RTOS SDK v3.4** чистым C: настоящие FreeRTOS-задачи вместо
кооперативного loop(), BSD-сокеты вместо WiFiServer/ESP8266WebServer,
NVS вместо EEPROM-сектора. Протокольная логика перенесена байт в байт.

Включает **прозрачный мост Modbus TCP (порт 502)** к родной карте регистров
прибора: SCADA работает с расходомером по сети ровно как по RS-485,
через ту же командную строку сервисной консоли (`MB`/`MBR`, см. ниже).

## Архитектура

| Файл | Назначение |
|---|---|
| `src/main.c` | `app_main`: boot_task (дерево → wifi → стартовая проверка OTA → веб) |
| `src/protocol.{c,h}` | **чистое C-ядро**: парсер листинга/значений, руссификация, HHMM/DDMMYY, 'm'-кадры, промпт-матчер. Без SDK-зависимостей — этот же файл компилирует хост-тест (`tools/test_parser.cpp`) |
| `src/ske02.c` | задача **meter** (стек 3840): uart 115200, стейт-машина WAKE→LIST→IDLE, очередь команд (SET/RUN/CMD/RESCAN/REBOOT/MODBUS/SETTIME), опрос 'm' 5 Гц; сюда же пуш WiFi-инфо в меню прибора (WIP/WMAC/WRSSI/WNET/WOTA), heartbeat `m ok … heap … hwm` (отдельной задачи мониторинга нет) |
| `src/espcons.c` | **консоль шлюза на USB-UART** (режим USBESP прибора, UART0/GPIO14) + весь OTA-механизм: download/update_gateway/update_meter, ping, проверка сервера (раз в сутки и до старта веба), отложенная прошивка прибора (NVS-намерение) |
| `src/wifi.c` | задача **wifi**: перебор сохранённых сетей, фолбэк в AP-портал, события esp_event |
| `src/web.c` | **esp_http_server** (3 слота, lru-purge): SPA-страницы из `www/` (собираются в `src/pages.h` скриптом `tools/pages.py`), JSON API; главная: виджеты + шапка «СКЭ-02 №NNNNNN» + низ `SKE02_HW_FW · IP` (всё из единого опроса `/api/values`) |
| `src/mb_pass.c` | **прозрачный Modbus TCP (502)**: MBAP → `MB <hex>` → RTU-движок прибора. Лимит клиентов: **2 при включённом вебе, 5 при выключенном** (фича «WEB panel» в меню прибора); каждый клиент ~3.2К кучи на время сессии |
| `src/ntp.c` | SNTP: **окно 12 ч** (метка последней синхронизации в NVS — мягкий ребут сервер не дёргает), после потери питания время берётся из DS1307 прибора (строка `clock` в `i`), fallback на NTP через 5 минут, ручная кнопка «Синхронизировать» |
| `src/urclock.c` | программатор urboot: прошивка ATmega128 по GPIO5-сбросу на 1 Мбит при погашенном WiFi |
| `src/dns.c` | captive-DNS (udp/53) для портала |
| `src/storage.c` | NVS: сети WiFi, адрес сервера обновлений, метки OTA |

## Сборка

```bash
pio run -e esp8266_modern_rtos            # сборка
pio run -e esp8266_modern_rtos -t upload  # прошивка
python tools/gen_sdkconfig.py             # перегенерация sdkconfig при смене опций
cmd /c tools\run_parser_test.bat          # хост-тест протокольного ядра
```

Платформа — [freedib/platform-espressif8266](https://github.com/freedib/platform-espressif8266)
+ SDK v3.4; `tool-genbin-esp8266` в реестре PlatformIO отсутствует и
переопределён на git-копию freedib (нужен только nonos-билдеру, но
объявлен обязательным в манифесте платформы).

## Отличия от Arduino-версии

- **Задачи вместо loop-пауз**: листинг принимается задачей meter в своём
  собственном контексте — веб/Modbus никогда не останавливаются, параметр
  `skeCapturing` не нужен.
- **Очередь команд**: веб-обработчики отправляют запросы (SET/RUN/UNLOCK)
  в задачу meter и ждут семафора — UART трогает ровно одна задача.
- **NVS** с wear-levelling вместо ручного CRC8-сектора.
- Мониторинговое окно (MeterData, 1 Гц 'm') и все прочие функции — те же.
- Хост-тест теперь компилирует **настоящий** `protocol.c` вместо ручной
  копии парсера — источник истины один.

## Прошивка на стенде

По-прежнему действуют правила стенда: COM28 один и коммутируется
перемычкой ATmega128 ↔ ESP8266, у ESP есть кнопка BOOT. **Перед прошивкой
шиза — пауза и явный запрос подтверждения**: только пользователь
коммутирует перемычку и держит BOOT.

## Защищённые OTA-пакеты (.skpak)

Обновления принимаются **только** в формате `.skpak` (см. `tools/ota_pack.py`):
заголовок с Ed25519-подписью + AES-128-CTR-нагрузка. Подпись проверяется
публичным ключом в `src/ota_sec.c`; провал любой проверки — образ не
активируется. **Единый артефакт — бандл** (образ ESP + hex прибора под
одной подписью, `pack-all`); отдельные пакеты шлюза/прибора собираются
только для curl-заливки.

Сборка (`pack_after_build.py` после каждой прошивки):
- `dist/system_full.skpak` + `dist/versions.txt` — для **сервера обновлений**
- `dist/curl/gateway.skpak`, `dist/curl/meter.skpak` — для `curl --data-binary
  @… /api/ota/upload` и `/api/avr/upload` (нужен включённый веб)

### Схема обновления

| Путь | Как |
|---|---|
| Консоль шлюза | `url <адрес>` → `check` (versions.txt) → `download` (качает бандл, веб гасится, прогрессбар, Ctrl+C) → `update_gateway` (слот+ребут) / `update_meter` (просит **вытащить USB-кабель**, намерение переживает ребут шлюза в NVS, urboot-прошивка стартует сама после возврата линии прибору) |
| Меню прибора (OTA update) | строка «Новая версия! NNNN / Нет обновлений / Сервер недоступен» (шлюз пушит `WOTA` раз в ~5 с; проверка сервера — при старте до веба и раз в сутки). «Update Device?»/«Update Gateway?» идут только при подтверждённой доступной версии, иначе экран «Недоступно» с причиной |
| curl | см. `dist/curl/` выше |
| Кабель | как обычно (esptool / urclock) |

Планировщик экономии: тяжёлые операции (скачивание 8К стека, urboot 6К,
проверка 4К) — временные задачи из кучи; консольные команды исполняются
в meter_task и никогда не тянут сеть/крипто напрямую.

## Известные платформенные грабли (оплачено)

- **newlib `%f` в двух задачах одновременно = IllegalInstruction с float-битами в PC** (общий reent, per-task сломан в SDK). `%f` разрешён только внутри однозадачного httpd; в остальных местах целочисленный `fmt_float`/целые.
- **Логи wifi-блоба в UART0** лечатся только сильным `ets_putc` в `debug.c` (SDK-шный ets_printf пишет прямо в FIFO-регистры).
- SDK-логи и весь ROM-вывод — на UART1 (GPIO2), рабочая линия UART0 чистая.

Модель угроз: подпись — настоящая граница (приватный ключ не покидает
хост упаковки); AES прячет образ от снифера в LAN. Физический доступ к
шлюзу вне модели (ESP8266 без eFuse). Утрата приватного ключа =
перегенерация ключей + перепрошивка шлюза с новым публичным ключом.
